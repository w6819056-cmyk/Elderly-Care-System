# 门店独立入口与员工入职申请

## 已确定范围
企业系统内部新增门店独立路径，不新增部署系统或平台用户库。员工申请由本企业总部审批，不能直接创建账号或自选角色。

## 路由与页面
- /stores/:storeNo：公开门店首页。营业门店展示门店名称、编号、企业名称及员工登录/申请入口。没有配置的运营内容不伪造。
- /stores/:storeNo/login：门店专属员工登录。登录后必须由服务端校验员工属于此门店，不能只由前端跳转检查。总部账号使用总部入口。
- /stores/:storeNo/register：姓名、期望账号、初始密码、手机号、可选邮箱；绑定当前门店，不能指定角色或数据范围。
- /store：沿用既有门店员工工作台。独立入口复用企业员工会话，登录后按当前门店上下文显示。
- 总部门店卡片增加打开首页、复制门店入口；新建门店后使用 storeNo 生成地址，不允许修改为其他企业地址。
- /hq/staff-applications：按权限及数据范围查看申请列表、详情、通过/驳回。

## 申请生命周期
PENDING → APPROVED / REJECTED，终态不可重复审批。通过时由总部明确选择 STORE 域角色。审批事务内锁定申请、重新校验门店营业状态与账号唯一性、调用现有 IAM 规则、写入员工及角色、更新申请并记录审计。账号冲突或门店停用导致事务回滚，申请仍待处理，不生成半完成账号。

提交时密码至少 12 位，只保存密码哈希，不记录或返回密码；申请通过后使用提交时密码登录。公开提交返回通用受理结果与申请编号，不返回员工资料或其他账号是否存在。驳回原因供总部查看，首批不做无身份校验的公开申请查询。

## 权限与隔离
公开接口仅精确放行门店展示、专属登录和申请提交。门店页面仅返回营业状态与展示所需字段，不返回员工、联系信息、模块授权内容或企业内部标识。非营业门店不接受申请。

总部查看和审批复用 iam.staff.view / iam.staff.manage，后端按门店范围裁剪和二次校验。企业所有者保护、角色域约束和注册权限目录继续生效。公开注册不能获取总部员工身份。平台总端不接收注册申请资料。

## 结构与迁移
新增独立 V5 迁移，创建员工申请表及状态/门店索引。门店门户控制器与申请服务独立于 HqIamController，员工创建仍复用 TenantIamService。对外登录绑定门店采用 TenantStaffAuthService 专用入口，避免签发错误门店令牌。

页面复用企业主题及 API 客户端，但公开请求不依赖员工登录状态。服务端限制提交频率与输入长度；前端按钮防重复不代替后端约束。

## 验收
营业门店公开首页可读；停业门店禁止注册；申请不会直接生成员工或令牌；审批创建 STORE 员工且绑定原门店；重复审批不重复开户；跨范围审批拒绝；错误门店登录拒绝；新员工无法进入总部；权限与模块入口仍由服务器控制；已有登录及组织测试不回归。

## 首批边界
门店介绍、商品与服务展示、在线支付、用户端会员注册、短信通知、申请撤回与重新提交策略不在本次。后续按模块接入。
