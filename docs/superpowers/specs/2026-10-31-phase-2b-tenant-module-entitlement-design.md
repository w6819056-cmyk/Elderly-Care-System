# 阶段 2B：模块授权同步与门店启用守卫设计

日期：2026-10-31  
设计依据：[模块化多企业养老 SaaS 平台设计](2026-10-29-modular-multi-tenant-saas-design.md)  
阶段 2A：[企业组织与权限底座设计](2026-10-31-phase-2a-tenant-organization-iam-design.md)  
阶段路线图：[模块化 SaaS 实施路线图](../plans/2026-10-30-modular-saas-delivery-roadmap.md)

## 目标与范围

为每家企业独立部署的 `tenant-app` 建立付费模块的本地授权镜像、总部启用和门店名额分配，以及统一的运行时访问守卫。企业断网时，已验签且仍在离线宽限期内的授权可继续使用；超过平台配置的 7 天离线宽限期后，付费模块进入只读。模块授权到期后保留 3 天收尾期，之后只读；企业数据不自动删除，保留和删除由企业自行决定，删除须走企业内部上报、总部审批、24 小时等待期和执行流程（数据删除流程不在本阶段实现）。

本阶段复用平台现有 Ed25519 授权文件、实例签名认证、激活、心跳、拉取和 ACK 接口。实现平台授权快照字段兼容、租户本地授权同步及验签、总部模块管理 API、逐模块门店分配、权限定义注册、统一模块守卫和最小总部管理界面。平台不接收企业客户、员工、订单、门店经营或其他业务明细；只接收实例身份、软件版本、授权版本和心跳状态。

本阶段不实现模块业务功能、平台购买/续费交易流程、自动删除过期数据、动态加载任意插件、断网授权绕过，也不实现门店端复杂工作台。试用模块可在本地启用且不能作为其他模块的正式依赖；本阶段展示已有授权状态，不改造平台套餐购买 UI。

## 责任边界

| 数据/决策 | 权威方 | 租户端保存内容 |
| --- | --- | --- |
| 企业模块正式授权、授权类型、起止时间、逐模块总名额、授权版本 | 平台签名授权文件 | 原始签名文件及解析后的只读授权镜像 |
| 模块是否由总部启用 | 企业总部 | 企业本地启用记录 |
| 某模块分配给哪些门店 | 企业总部 | 企业本地分配记录；不回传平台 |
| 当前门店能否调用模块 | 租户端运行时策略 | 根据授权、启用、分配、门店状态和离线状态实时计算 |
| 模块数据保留与删除 | 企业总部/企业政策 | 本阶段仅提供模块状态和导出入口所需状态，不执行删除 |

平台授权中的 `storeQuota` 是该企业该模块可分配的最大门店数，不代表某具体门店已获分配。租户端不得仅凭平台签名文件就允许任意门店使用付费模块。

## 方案与架构

采用租户主动拉取的授权快照方案。平台继续签发完整、版本化、企业与部署实例绑定的 Ed25519 `LicenseDocument`；租户端使用配置的受信公钥验签并在本地持久化。租户总部在业务库内管理门店启用和分配。每次请求的服务端守卫从本地授权快照与企业分配记录计算结果。该方案复用现有控制面协议、适合单企业独立部署和断网运行，并避免平台保存门店业务关系。

边界如下：

```text
平台控制面
  企业正式授权与总名额 -> 签名 LicenseDocument -> 心跳/授权拉取/ACK
                                                |
                                     企业主动 HTTPS 出站
                                                v
企业 tenant-app
  验签与版本防回退 -> 本地授权快照 -> 总部启用 -> 门店分配
                                                |
                                  ModuleAccessGuard
                              菜单元数据与后端接口共用
```

不采用平台在线逐请求鉴权，因为其会让企业业务可用性依赖平台在线；不采用只隐藏前端菜单的授权，因为直接调用 API 可绕过。

## 授权同步协议

### 激活与信任材料

首次绑定沿用现有激活码流程。企业安装程序生成独立实例密钥对和稳定安装 ID，公钥、指纹、安装 ID、租户数据库标识提交激活；私钥只保存在企业服务器受限目录或密钥管理服务中，禁止写入数据库、日志、前端或版本库。激活响应包含实例公开 ID、企业 `orgNo`、平台公钥标识和初始授权快照。平台根/签发公钥通过受信安装包或明确配置注入，不能由未验签的响应替换。

### 拉取与验签

- 企业端每 6 小时主动调用平台心跳；心跳使用现有请求时间戳、随机数和实例私钥签名。平台端验证实例签名并返回平台时间、企业/实例状态和当前授权版本；有新版本时返回签名授权文件或要求租户调用现有授权拉取接口。
- 同步必须验证 Ed25519 签名、算法与 `keyId`、企业 `orgNo`、实例 ID、实例指纹、有效时间、schema 版本、模块代码唯一性、授权字段范围和授权版本。
- 接受版本必须严格大于本地版本；相同版本且相同文件摘要按幂等成功处理；低版本拒绝并审计，不能覆盖本地状态。相同版本但内容摘要不同视为平台协议安全错误，拒绝并告警。
- 验签和完整性校验完成后，在一个本地事务中写入原始文件、摘要、版本、签发/生效时间、同步状态及模块授权镜像；提交成功后才 ACK。数据库事务失败时不 ACK，重试可安全重复。
- ACK 应包含版本和文件摘要；平台端 ACK 幂等。旧平台接口若只接受版本，2B 需保持兼容并在响应/请求 DTO 增加摘要字段（可选兼容期），最终由版本与摘要共同确认。
- 平台返回企业暂停、实例撤销、实例不匹配等明确控制面拒绝时，租户记录状态并停止付费模块写操作；不因一次网络超时把企业切到停用状态。
- 网络错误、平台 5xx、超时不会清除或回退本地授权。使用最后一次成功同步时间计算离线窗口。联网恢复后立即尝试同步，随后回到 6 小时周期；失败使用有上限的指数退避并加随机抖动。
- 服务端时间以最后成功同步的平台时间为锚点，结合本地单调经过时间计算授权时间；记录系统墙钟明显回拨。重启后使用持久化的平台时间锚点及可信本地时间，检测到无法可靠判断时间时，付费模块降为只读并要求重新同步，不得延长授权。

### 授权状态

平台授权仍使用现有 `ACTIVE`、`WIND_DOWN`、`READ_ONLY` 等概念。租户运行时按以下顺序计算，最终只能取最严格状态：

| 条件 | 企业总部模块状态 | 门店模块状态 |
| --- | --- | --- |
| 无正式授权、已撤销或企业/实例被平台停用 | `UNLICENSED` / `SUSPENDED` | 禁止访问；保留数据只读查看入口按本地权限开放 |
| 正式授权有效，但总部未启用 | `DISABLED` | 不可访问 |
| 已启用，门店未分配 | `NOT_ASSIGNED` | 不可访问 |
| 门店已分配且正常营业、在线授权有效 | `ACTIVE` | 正常使用 |
| 授权到期且仍在 3 天内 | `WIND_DOWN` | 允许查看和完成/收尾已有业务；禁止新增主要业务，细分动作由模块守卫策略声明 |
| 超过到期时间 3 天 | `READ_ONLY` | 只读，不得新增或变更业务数据 |
| 最后成功心跳不超过 7 天且授权时间有效 | 保持上述授权状态 | 保持上述授权状态 |
| 最后成功心跳超过 7 天 | `OFFLINE_READ_ONLY` | 只读；免费基础底座仍可用 |
| 门店 `SUSPENDED` 或 `CLOSED` | 不改变总部授权及名额 | 禁止经营写入；历史数据按权限查询/导出 |

试用授权使用 `TRIAL` 来源，按平台签名起止时间计算，仅授予本模块；不能满足其他模块的正式依赖。永久授权不因时间到期，但仍受企业/实例停用、离线宽限、总部开关和门店分配约束。若多种状态同时成立，守卫按 `SUSPENDED/UNLICENSED`、`OFFLINE_READ_ONLY`、`READ_ONLY`、`WIND_DOWN`、`DISABLED/NOT_ASSIGNED`、`ACTIVE` 的限制优先级拒绝或收紧操作。

### 到期和离线能力

`ACTIVE -> WIND_DOWN -> READ_ONLY` 按平台签名授权的 `expiresAt` 和平台时间锚点计算，过期后 3 天（含边界）为收尾期，超过边界进入只读。离线宽限从最后成功平台同步时间计算，7 天整仍可按本地授权运行，超过 7 天只读。若模块授权先到期，使用更严格的模块状态。平台停止续签不会清除授权历史或企业数据。

`WIND_DOWN` 允许的命令须由模块注册表显式声明，例如读取、取消尚未开始的预约、完成已接单服务、记录已开始服务的收尾结果；未声明的写操作一律拒绝。通用守卫不猜测业务语义。

## 企业总部模块与门店分配

总部 API 使用 `/api/tenant/v1/hq/modules/**`，接受 2A 的 `TENANT_STAFF` 令牌、总部角色、权限 `core.module.view`、`core.module.manage` 或 `core.module.assignment.manage`，并要求有效总部数据范围。门店员工无权启停模块或更改分配。

建议接口：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/tenant/v1/hq/modules` | 返回模块目录、平台授权、启用状态、已用/总名额、试用状态和到期状态 |
| `PUT /api/tenant/v1/hq/modules/{moduleCode}/activation` | 幂等启用/停用；启用前校验正式或试用授权及依赖 |
| `GET /api/tenant/v1/hq/modules/{moduleCode}/assignments` | 查询该模块的门店分配和门店状态 |
| `POST /api/tenant/v1/hq/modules/{moduleCode}/assignments` | 分配给一个门店；支持 `Idempotency-Key` |
| `DELETE /api/tenant/v1/hq/modules/{moduleCode}/assignments/{storePublicId}` | 总部显式撤销分配并释放名额；重复撤销幂等成功 |
| `GET /api/tenant/v1/hq/license/status` | 查看脱敏后的实例、最近同步时间、版本和离线剩余宽限 |

业务规则：

1. 每个模块单独计名额；同一模块同一门店最多一条有效分配，同一门店可以分别获得不同模块。
2. 只有授权有效、总部已启用、模块依赖满足且剩余名额大于 0 时可分配。正式模块依赖须满足已有有效**正式授权**；试用、已到期或只有菜单权限都不满足。
3. 名额写入使用事务和数据库唯一约束 `(module_code, store_id)`，并对该模块授权/计数行加锁或用原子条件更新，避免并发超额。重复相同请求返回原分配，不重复占额。
4. 门店停用或撤店不删除分配、不释放名额；总部仍可查看并显式撤销。恢复门店后原分配可恢复使用，但仍须授权有效且总部模块开启。
5. 总部停用模块阻止所有门店访问，但保留分配记录和名额；重新启用时恢复未撤销分配。
6. 授权版本更新导致名额降低至低于当前分配数时，禁止新增分配并显示超额；既有分配不静默删除。总部可自行撤销直至回到额度内。租户不得自行扩大平台授权总额。
7. 试用领取/授权在本地显示并立即生效，仅当平台签名授权快照包含有效试用模块时；总部不能伪造试用期限。
8. 所有启停、分配、撤销、同步拒绝和离线降级写入 `audit_tenant_log`，包括操作者、模块、门店、授权版本、traceId 和非敏感前后状态。

## 模块注册契约与统一守卫

每个已编译进租户程序的模块，通过 `care-module-api` 注册不可变 `ModuleDescriptor`，至少包括：`moduleCode`、版本、名称、权限定义、菜单/路由元数据、后端资源到操作的模块映射、正式模块依赖、收尾期允许的命令集合。免费基础底座声明为 `core`，不经过付费授权守卫，但仍执行登录、角色权限、数据范围和门店状态校验。

模块实现不得自行读取授权表或自行判断“是否购买”。控制器/应用服务统一调用 `ModuleAccessGuard.require(moduleCode, operation, accessContext)`；守卫返回 `ACTIVE`、`WIND_DOWN`、`READ_ONLY` 等能力，写命令按当前状态与模块声明决定放行。无模块代码或未注册资源默认拒绝。守卫必须在应用服务/服务层执行，不能只依赖 Controller 注解，防止内部调用绕过。

菜单和路由元数据调用同一 `ModuleAccessQuery`，仅用于生成可见入口；隐藏菜单不构成安全边界。客户端提交的 `moduleCode`、`storeId`、权限码不得作为可信输入。模块代码由服务端路由映射确定，门店 ID 仍需通过 2A 数据范围和当前企业数据校验。最终访问条件为：

```text
员工有效且 TENANT_STAFF
AND 企业角色权限允许
AND 请求对象在员工数据范围内
AND 门店状态允许此操作
AND 模块已授权且总部已启用
AND 当前门店有该模块有效分配（总部级操作除外）
AND 授权/离线/收尾状态允许此操作
```

错误码沿用 2A 稳定错误结构，新增：`MODULE_NOT_LICENSED`、`MODULE_DISABLED`、`MODULE_NOT_ASSIGNED`、`MODULE_QUOTA_EXCEEDED`、`MODULE_READ_ONLY`、`LICENSE_SYNC_REQUIRED`、`LICENSE_SIGNATURE_INVALID`、`LICENSE_VERSION_ROLLBACK`、`MODULE_DEPENDENCY_UNSATISFIED`。响应不包含签名私钥、内部文件路径或原始密码学异常。

## 数据迁移与配置

只在 `backend/core/care-core/src/main/resources/db/migration/tenant` 追加新的 Flyway 迁移（预期版本 `V3`，实际版本须先检查分支上迁移顺序）；不修改已发布的 V1/V2，不写入 `application-dev.yml` 的 DROP 初始化。

租户库至少保存：

- `lic_license_snapshot`：当前有效版本、原始签名 JSON、SHA-256 摘要、平台时间锚点、最后同步时间、同步状态和版本号。对企业/实例唯一。
- `lic_module_entitlement`：由签名快照投影的模块授权类型、状态、起止时间、永久标记、平台总名额、来源版本；仅同步事务更新，不供总部直接编辑。
- `core_enterprise_module`：总部启用开关、操作者、更新时间和乐观锁版本。
- `core_store_module_assignment`：模块、门店、分配状态、分配/撤销操作者与时间、幂等键；唯一有效分配约束。
- `lic_sync_attempt` 或等效审计记录：结果码、尝试时间和 traceId；不得保存私钥或完整请求签名头。

私钥、公钥信任根和平台地址由环境/部署密钥配置管理，不进入业务表或仓库。对测试环境可注入固定密钥对。所有时间由 `Clock` 注入，避免依赖宿主机默认时区。

## 安全、并发与故障处理

- 对平台请求沿用实例签名认证和 nonce 防重放；校验 TLS，连接/读取超时明确配置。
- 授权文件严格限制大小、模块条数、字符串长度和 schema 版本，拒绝未知必需字段或重复模块代码。
- 先验签再解析为可执行授权；任何失败保留上个已验签快照并记录安全审计，不可把失败响应视作空授权并覆盖。
- 数据库事务内快照版本、摘要和模块投影原子更新；ACK 发生在提交后。
- 同步任务用单实例租户锁/数据库租约防止多副本同时刷新；多副本服务请求读取同一数据库快照。
- 总部并发分配靠唯一约束和额度原子校验兜底；对门店状态变更与分配使用一致事务顺序，门店关闭后仍保留分配。
- 平台拒绝实例、授权撤销等签名认证的控制面响应可立即收紧权限；网络超时不得触发撤销。
- 缓存只缓存授权快照/解析结果且必须有版本；启停、分配撤销或同步提交后立即失效。不得在进程内缓存导致重启或多副本间权限不一致。

## 测试与验收

1. 授权签名有效且企业/实例/指纹匹配时成功落库并 ACK；伪造签名、错误 keyId、企业不匹配、实例不匹配、模块重复和非法时间均拒绝且不改变当前快照。
2. 更高版本覆盖成功；相同版本相同摘要重放幂等；相同版本不同摘要、低版本和 ACK 前事务失败均按协议处理。
3. 平台暂时不可达时保留已签名授权；6 小时调度可注入时钟测试；7 天边界可用，超过 7 天进入只读；联网恢复立即同步。
4. 模块授权到期边界正确经历 `ACTIVE -> WIND_DOWN -> READ_ONLY`；永久模块不按日期到期；试用不满足正式依赖；企业/实例撤销立即禁止写入。
5. 总部未购买模块、未启用模块、依赖缺失、门店未分配时门店 API 均拒绝；总部级授权管理不错误要求门店分配。
6. 同一门店重复分配幂等；并发分配不超额；不同模块额度独立；停用/撤店不释放；总部撤销后释放且可重新分配。
7. 模块守卫同时覆盖菜单查询、Controller 请求和服务层内部调用；篡改请求的 `moduleCode` 或 `storeId` 不能越权。
8. `WIND_DOWN` 只放行注册表明确列出的收尾命令；只读状态下所有写入拒绝，免费 core 模块仍可用。
9. 审计包含关键授权与分配动作但不泄露密钥；新增租户 Flyway 在 H2/MySQL 8 空库执行；现有 2A 和阶段 0/1 回归测试通过。
