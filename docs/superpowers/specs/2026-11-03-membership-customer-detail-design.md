# 总部客户详情中的会员摘要

## 目标

当会员模块已安装、启用且授权有效时，总部有权查看客户资料的员工可以在客户详情中查看该客户的会员摘要。没有会员模块或会员模块未授权时，基础客户管理继续正常工作，不显示会员区域。门店员工继续使用会员模块的客户主动出示编号查询流程，不在门店客户列表或详情中自动显示会员信息。

## 当前基础

- 企业客户管理由底座 `CustomerManagementService` 实现，详情先按员工的数据范围确认客户，再返回该范围内的预约。
- 外置模块通过 `CustomerFeatureProvider` 向已登录消费者提供本人专属页面摘要；会员模块已经实现该接口。
- 会员模块业务服务已有只读 `card(customerPublicId)`，返回是否为会员及等级和权益摘要。
- 外置模块 HTTP 处理器通过 `@ModuleOperation` 由宿主检查模块授权、员工权限和门店范围。
- 会员服务当前的员工操作使用 `StaffAccessApi`，会员读权限代码为 `membership:member:read`。

## 设计

### 扩展接口

在 `care-module-api` 新增面向员工客户详情的窄接口，例如 `CustomerManagementFeatureProvider`。提供者声明模块代码、读取所需权限代码，并接收已由宿主确认可见的客户公开 ID，返回 JSON 友好的摘要对象。会员模块在其配置类中注册该提供者并委托给现有会员服务；底座客户管理不依赖会员实现、会员数据表或会员模块 Maven 工件。

### 宿主校验与响应

新增总部客户详情扩展读取入口，路径归属企业客户管理 API。执行顺序为：

1. 验证总部员工身份及 `core.customer.view`。
2. 按与客户详情相同的数据范围规则验证该客户可见；不可见客户返回与客户详情一致的 404，不调用任何模块提供者。
3. 只对已加载的外置模块查找提供者，并确认对应企业模块处于启用状态、平台实例许可证有效且模块授权在当前时间有效。
4. 对每个提供者单独要求其声明的权限；缺少模块权限时只省略该模块的数据，不泄漏其他模块内容。
5. 聚合为 `{ items: [{ moduleCode, data }] }`。无可用提供者时返回空数组，基础客户接口与详情结构保持兼容。

扩展入口仅允许总部员工。门店的客户列表、详情和既有会员主动查询接口不变。请求体和查询参数均不得指定员工身份或覆盖数据范围；客户 ID 只能来自已授权的路由路径。

### 前端行为

总部客户详情打开后，独立请求扩展数据。已有客户资料先正常展示；扩展加载失败时显示局部错误及重试操作，不覆盖或阻断客户资料和预约。存在会员摘要时显示会员状态、等级和权益；无模块数据时不显示会员卡片。门店不请求该扩展接口，也不在其客户详情中展示会员信息。

### 隐私与错误处理

- 访问边界由服务端执行，隐藏菜单或按钮不作为授权措施。
- 范围外客户不可通过扩展端点探测会员状态。
- 无模块权限时返回空模块结果，不将该权限错误混淆为基础客户查看失败。
- 模块提供者抛错时按模块隔离失败；不返回栈信息、SQL 或授权快照内容。
- 会员摘要只返回当前 UI 所需字段，不返回会员流水、内部数据库 ID 或其他企业信息。

## 验收

- 总部数据范围内且拥有 `core.customer.view` 与 `membership:member:read`、模块已安装启用且授权有效时，客户详情能读取其会员摘要。
- 缺少会员读取权限、模块未安装、未启用、许可证无效或授权过期时，接口返回空扩展项且客户详情仍可用。
- 区域范围外客户的扩展请求返回 404，且会员提供者不会被调用。
- 门店调用总部扩展接口被拒绝；门店主动出示编号的现有会员查询行为不回归。
- 前端总部显示会员摘要；无扩展数据时不渲染空白卡片；扩展请求失败可以独立重试。
- 现有客户列表、客户详情和消费者本人会员权益测试保持通过。

## 测试策略

后端先写宿主集成测试验证授权、模块状态和数据范围，再实现提供者聚合；会员模块测试验证其 provider 委托使用客户摘要；前端测试覆盖总部加载、空态、独立错误及门店不调用扩展接口。使用隔离测试数据库，不修改本地预览企业的许可证、模块表或客户数据。

## 非目标

- 不恢复或重签当前预览企业的暂停授权。
- 不改变门店会员主动查询权限和流程。
- 不自动将电话相同的客户合并，不扩大跨门店预约或消费明细可见范围。
- 不把会员信息写入基础客户表或基础客户详情 DTO。
