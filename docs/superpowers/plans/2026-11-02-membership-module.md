# 会员等级模块实施计划

沿用已确认的会员等级设计，通过独立 thin JAR 和 .caremod 包交付，不把会员实现预编译进企业底座。

1. 底座提供 CustomerQueryApi、StaffAccessApi，只暴露企业内用户摘要和当前员工身份；消费者模块查询统一由宿主传入已认证的客户 publicId。
2. 会员模块自建 mem_level、mem_member、mem_change 及独立 V1 迁移。等级版本控制、改级行锁、唯一用户会员档案和变更流水必须同事务。
3. 总部管理等级与会员；门店仅凭用户主动出示的稳定编号查询最小会员卡，不开放客户搜索、他店消费或内部备注。消费者只查询自己。
4. 注册普通用户不自动入会；停用等级不删除现有档案，禁止新分配。首版权益为说明，不实现自动优惠、积分、储值或核销。
5. 模块 HTTP 操作在 manifest 中定义中文权限及资源操作，统一宿主授权守卫；总部动态模块页和消费者通用模块资料桥由宿主提供，业务规则不进入宿主。
6. 编译模块 JAR、组装前端/迁移/manifest，用仓库外发布私钥签名形成不可覆盖的1.0.0包。验证注册加载、独立迁移、等级并发更新、开通/改级、越权与未授权拒绝、各端页面。
7. 预览企业尚未配置正式激活及执行器，不能伪造已安装；交付可安装包和测试结果，不直接插入演示授权或绕过校验。
