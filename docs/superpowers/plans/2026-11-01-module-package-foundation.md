# 模块安装底座 Implementation Plan

**Goal:** 让新模块通过平台收录、企业下载并经总部确认安装，不再要求把每个模块预编译进底座。

**Architecture:** 平台存储发布包和版本元数据，企业安装器验证包、授权、兼容性与依赖；模块在企业服务器受控重启后运行。包校验器由双方共享，不执行包内代码或 SQL。

**Tech Stack:** Java 17、ZIP、JSON、Ed25519、SHA-256、现有 Spring Boot 和 React。

## 全局边界

- 客户业务数据不上传平台；平台模块包不携带客户数据。
- 权限沿用现有 `module:resource:operation`，基础权限现有点号不改。
- 新权限不自动分配普通员工；授权和安装独立。
- 数据库只新增独立迁移，不重写已执行脚本。
- 更新需总部确认，不允许上传即自动执行；不承诺数据库自动逆迁移。

## 阶段 A：模块包协议与共享校验器

- [x] 编写包结构、签名、版本、依赖及接口约定。
- [x] 新建 libs/care-module-package，依赖 care-module-api 和 Jackson。
- [x] 测试有效签名、篡改、未知发布者、未声明文件、目录穿越、重复路径、摘要错误和大小限制。
- [x] 实现共享验证，返回验证后的元信息与受保护的文件内容，不解压执行。
- [x] 编写可复现的最小包构建及验证测试。

## 阶段 B：平台收录与分发

上传使用平台权限，调用共享验证器；已发布 code/version 不可覆盖；包落盘和数据库记录有一致性恢复机制。发布签名私钥在发布工具中保存，不从客户端包获取信任公钥。提供版本列表、下载和上架管理，客户端下载需企业实例认证及授权。测试上传失败不产生可下载版本。

## 阶段 C：企业安装与启动

安装准备检查授权、底座范围、依赖程序版本及正式依赖授权、磁盘与备份；生成待确认安装计划。总部确认后安装器持有全局锁，解压至 staging，保存日志，停机备份与迁移，切换版本并启动健康检查。安装计划记录包摘要，防止确认后换包。进程重启需要独立安装助手，不能只重启自身。

前端通过模块清单加载经过发布签名保护的前端资源；明确共享 React ABI 和模块导出入口，路由权限仍由服务器授权。后端从外置模块目录启动加载，去除固定会员等实现依赖前先证明模块 Bean、接口与迁移可注册，不能把上传 ZIP 等同于成功加载。

安装失败区分迁移前与迁移后：迁移前恢复程序即可，迁移后必须备份恢复或人工修复，状态为 RECOVERY_REQUIRED；禁止盲目回退程序继续写入。

## 阶段 D：最小模块完整验收

新模块不修改底座源码；上传、下载、总部确认、启动后出现页面与权限，模块表创建且重新启动不重复迁移。授权不足和未分配门店拒绝使用，更新失败有明确状态。通过后才接会员等级业务。
