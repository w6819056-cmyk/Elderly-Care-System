# 外部安装执行器与模块运行时

目标：独立进程执行已确认的安装计划，企业进程启动时读取经过签名校验的模块索引，健康检查和启动回执匹配后才标记 ACTIVE。

1. 定义 ModuleEntrypoint，新增共享运行库：安全落盘、原子索引、隔离包命名空间校验、从外部 JAR 提供配置类；测试真实编译的插件。
2. 企业应用启动注册外部配置和模块描述、中文权限名，ApplicationReady 后写入带 planId/sha 的运行回执。原有占位模块保持兼容，但外部同编号安装后替换占位描述。
3. 新增 V11 执行日志与共享授权策略；安装进程与确认接口都用相同校验，不依赖 UI 判断。
4. 新增 installer-app：配置由部署人员提供，命令使用参数数组执行；不运行包内安装脚本。使用文件锁和数据库锁，先校验再停服、备份；执行每个模块独立 Flyway 历史；切换索引并启动；对比健康响应与启动回执。
5. 失败状态：校验/备份阶段失败为 FAILED 并尝试恢复旧服务；迁移开始或新版启动后失败为 RECOVERY_REQUIRED，不自动恢复旧程序继续写入。中断留下执行日志，禁止自动重试不明确状态。
6. watch 模式定期写本机心跳，只在配置检查及锁持有正常时报告就绪。总部界面显示真实状态；默认不启动执行器，不操作现有客户数据库。
7. 使用隔离 H2、真实测试 JAR 和真实 Spring 上下文验证成功、备份失败、迁移失败、回执不符、篡改、并发锁、重新启动等路径。MySQL真实停服备份需部署配置，不冒充已在现有预览环境安装。
