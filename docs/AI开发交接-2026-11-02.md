## 2. 两套系统的边界

同一仓库，两套独立构建、部署的系统：

- 平台系统：我们公司服务器，管理企业账户、软件授权、模块销售、版本发布和更新分发。
- 客户系统：客户总部服务器，包含企业总部管理、门店管理、消费者网站；客户业务数据保存在客户自己的数据库。
- 平台不得获取企业消费者 openid、客户档案、业务订单等业务数据。跨系统同步仅传授权、实例、版本等必要信息。
- 平台权限域与企业权限域分离。企业总部自行创建角色、权限组并管理旗下门店；不得获得平台权限。
- 企业总部不充当门店。门店有独立价格、服务、页面和管理入口；企业客户身份可跨本企业门店识别。

当前核心技术：Spring Boot 3 / Java 17 / Maven 多模块，React + TypeScript + Vite，MySQL，Flyway 增量迁移。

## 7. 不要破坏的产品规则

- 模块各有自己的表和 Flyway 历史，通过稳定 API/公共 UUID 关联底座数据；禁止模块直接改其他模块的表。
- 已执行迁移不得改写，新增版本另加迁移。
- 每模块独立计算门店名额。停用/撤店仍保留已分配名额，直到总部手工撤销。
- 企业可以自己创建角色、权限组，但只能使用自己域内且已获授权的能力。
- 依赖要求已购买正式授权，试用不能替代正式依赖。
- 到期保留数据，按既定三天收尾和只读/导出设计处理；不能自动清空业务数据。
- 模块升级由总部确认；受控重启，不承诺任意 JAR 热替换。
- 联网校验与断网宽限遵循既有签名许可证策略；不可只在前端隐藏菜单作为授权验证。
- 平台与企业 UI 要区分。保留现有养老机构背景和半透明圆角卡片设计；企业端顶部固定横向胶囊菜单、大内容卡片内部滚动且隐藏滚动条，避免重新引入页面溢出。
