## 新管理端：双系统开发与部署

仓库包含两个独立构建、独立部署的管理端。它们不能共用 API 地址或登录会话：

| 系统 | 前端目录 | 开发地址 | `/api` 开发代理 | 生产 API 归属 |
| --- | --- | --- | --- | --- |
| 平台管理端 | `admin-platform/` | http://localhost:5174 | `http://localhost:8081`（平台控制面） | 我们管理的平台 API |
| 企业租户管理端（总部/门店） | `admin-tenant/` | http://localhost:5175 | `http://localhost:8082`（租户服务） | 客户自己部署的租户 API |

### 本地开发

平台和租户 API 应各自启动。然后在仓库根目录分别启动前端：

```powershell
npm --prefix admin-platform install
npm --prefix admin-platform run dev

npm --prefix admin-tenant install
npm --prefix admin-tenant run dev
```

Vite 将 `/api` 请求分别代理至平台 API 8081 和租户 API 8082。默认代理目标可在对应 app 目录的 `.env.local` 中用 `VITE_API_BASE_URL` 覆盖；`.env.example` 不绑定客户生产域名。

### 独立生产构建

```powershell
npm --prefix admin-platform run build
npm --prefix admin-tenant run build
```

平台产物在 `admin-platform/dist/`，租户产物在 `admin-tenant/dist/`。构建时通过环境变量为各自前端设置 API 地址：

```powershell
$env:VITE_API_BASE_URL = 'https://platform-api.example.com'
npm --prefix admin-platform run build

$env:VITE_API_BASE_URL = 'https://customer-tenant-api.example.com'
npm --prefix admin-tenant run build
```

示例域名只用于说明配置方式，部署时替换为实际地址；客户域名不得写入仓库。静态站点服务器应将 SPA 路由回退到各自 `index.html`，并将 `/api/` 反向代理到该前端所对应的 API。若前端直接访问跨域 API，API 还需按部署域名配置 CORS；也可由同一站点反向代理 `/api/`，避免浏览器跨域。

### 托管、数据和升级边界

- 平台管理端、平台 API、平台控制数据库部署在我们管理的平台基础设施。平台负责企业平台账户与模块授权；版本目录和签名更新包发布属于后续计划，本阶段尚未交付。
- 企业总部/门店管理端、企业租户 API、企业业务数据库由客户部署和维护在客户侧。企业员工与客户业务数据归客户租户系统管理，平台不因此接管企业客户明细。
- 品牌网站和小程序源码属于企业系统项目；公开访问入口使用约定的平台统一域名/AppID。企业租户 API 与业务数据仍由客户侧系统承载。
- 后续版本更新流程计划为：平台发布版本和签名更新包，客户侧更新代理校验签名与版本适用性，再等待企业总部管理员确认，由客户侧本地流程应用更新。该更新代理及实际升级流程不属于本阶段交付；架构不允许平台远程执行客户服务器命令或静默修改客户服务器。

## 一、数据库准备

宝塔面板中 MySQL 默认 `root` 密码需要确认，或新建专用账号：

```sql
CREATE DATABASE IF NOT EXISTS elderly_care
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

CREATE USER IF NOT EXISTS 'elderly'@'localhost' IDENTIFIED BY 'Elderly@2026';
GRANT ALL PRIVILEGES ON elderly_care.* TO 'elderly'@'localhost';
FLUSH PRIVILEGES;
```

对应的 `application.yml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/elderly_care?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
    username: elderly
    password: Elderly@2026
```

## 二、后端

```bat
cd /d E:\yanglao\backend
mvn clean package -DskipTests
java -jar target\elderly-care-backend-1.0.0.jar --spring.profiles.active=dev
```

或直接开发模式：

```bat
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```

说明：

- `dev` profile 会在启动时执行 `db/schema.sql` 与 `db/data-demo.sql`，**会先 DROP 再建表**，勿在生产使用。
- 生产启动去掉 profile，改为手工执行脚本，并设置环境变量：

```bat
set APP_JWT_SECRET=<32字节以上的随机串>
java -jar target\elderly-care-backend-1.0.0.jar
```

- 验证：访问 http://localhost:8080/swagger-ui.html 能看到接口列表。

## 三、旧版管理端（`admin/`）

开发：

```bat
cd /d E:\yanglao\admin
npm install --registry=https://registry.npmmirror.com
npm run dev
```

生产构建：

```bat
npm run build
```

产物在 `admin/dist/`，用 Nginx 托管并反向代理 `/api` 到后端：

```nginx
server {
    listen 80;
    server_name _;

    root /path/to/admin/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

## 四、小程序

1. 微信开发者工具 → 导入项目 → 目录选 `E:\yanglao\miniprogram`。
2. AppID 填自己的或选"测试号"（`project.config.json` 里当前为 `touristappid`）。
3. 详情 → 本地设置 → 勾选"不校验合法域名…"。
4. 后端地址在 `app.js` 的 `globalData.baseUrl`，开发者工具用 `http://localhost:8080`，真机调试改成电脑局域网 IP（如 `http://192.168.1.10:8080`），并确保手机与电脑同一网段、防火墙放行 8080。

正式发布前需要：企业主体小程序、配置服务器域名白名单（HTTPS）、申请订阅消息模板。

## 六、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 后端启动报 `Access denied for user` | 数据库账号密码不符 | 改 `application.yml` 或用环境变量覆盖 |
| 启动报 `Table 'xxx' doesn't exist` | 未启用 dev profile 且未手工建表 | 执行 `schema.sql` 与 `data-demo.sql` |
| 管理端登录提示"登录失败" | 后端未启动或端口不符 | 检查 8080 与 Vite 代理配置 |
| 小程序请求失败 | 未勾选"不校验合法域名"或 baseUrl 非本机可访问 | 见上文第四条 |
| 小程序 401 后自动跳登录 | token 过期（72h） | 重新登录 |
| 演示数据被重置 | dev profile 每次启动重建表 | 属预期行为，改用非 dev profile 即可保留数据 |
