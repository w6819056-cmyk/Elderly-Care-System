# 外部安装执行器与运行时接入（ABI v1）

## 部署边界

installer-app 是运行在客户服务器上的独立 Java 进程，不是平台服务器远程执行客户命令。平台仅分发签名包；客户数据库备份和 SQL 迁移都留在客户服务器。默认不会启动执行器。

企业端与执行器必须使用相同的包缓存、发布公钥和 runtime 目录。先部署本版企业程序，启动后会写 runtime-ready.json，即使尚未安装模块也会写入进程与端口回执。

## 模块后端接口

模块为 thin JAR：backend/module.jar。不能打入 Spring Boot、底座实现或其他模块实现；不能使用 JAR Manifest Class-Path、内嵌 JAR、META-INF/services 或自动配置注册文件。所有类只能放在 `com.smartelder.modules.<模块代码将连字符替换为下划线>` 包及子包中。

入口类有公共无参构造器，实现 care-module-api 的 ModuleEntrypoint：

```java
public final class Entry implements ModuleEntrypoint {
    public List<Class<?>> configurationClasses() { return List.of(MemberConfiguration.class); }
    public Map<String,String> permissionNames() {
        return Map.of("membership:member:read", "查看会员资料");
    }
}
```

configurationClasses 返回自身命名空间内的 Spring 配置类，不能返回底座配置。permissionNames 必须准确覆盖 manifest.module.permissionCodes。模块可通过配置类的 @Bean 依赖底座公开 API；不要直接查询别的模块表。

每个模块 HTTP Handler 必须声明 @ModuleOperation(resource="...", operation="...")，对应 manifest 中 resourceOperations 的同名操作。路径限制在 `/api/tenant/v1/modules/<模块代码>/` 下。写操作不能映射 GET/HEAD/OPTIONS。宿主拦截器统一检查员工权限、模块授权、门店范围、名额及启用状态；仅隐藏菜单不构成权限校验。

签名模块是我们发布的可信服务端代码，不是沙箱。签名确认发布来源和完整性，不保证代码没有缺陷，也不能防止客户服务器管理员修改自己的程序。发布前仍需代码审查和测试。

## 前端接入

门店入口声明在 manifest.frontendEntries.STORE，模块菜单 route 使用 `/modules/<模块代码>` 或其子路径。前端入口必须是单文件、自包含 ES module，默认导出 React 组件，宿主传入 React、workspace、route、request。不要打包第二份 React；当前入口不支持相对 import 或额外运行时依赖。

```javascript
export default function ModulePage({ React, request }) {
  return React.createElement('section', null, '模块页面');
}
```

宿主使用员工认证获取 `/api/tenant/v1/modules/runtime/<code>/entry`，服务器验证模块菜单访问资格及文件摘要后返回脚本。request 桥仅允许本模块接口前缀。企业总部和消费者动态业务页面的运行接入尚未实现，不应仅因包里声明了 HQ/CUSTOMER 就宣称可用。

## 执行器配置

配置 JSON 存放仓库外，由部署管理员维护。密码通过配置指定的环境变量读取，不能写进模块包。以下是格式示例，路径和服务管理命令需按客户环境填写：

```json
{
  "jdbcUrl": "jdbc:mysql://127.0.0.1:3306/customer_care?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai",
  "username": "customer_care_admin",
  "passwordEnvironment": "CARE_INSTALL_DB_PASSWORD",
  "runtimeDirectory": "D:/care/data/module-runtime",
  "cacheDirectory": "D:/care/data/module-install",
  "trustDirectory": "D:/care/config/module-publisher-keys",
  "coreVersion": "2.1.0",
  "stopCommand": ["C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe", "-NoProfile", "-File", "D:/care/ops/stop-tenant.ps1"],
  "startCommand": ["C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe", "-NoProfile", "-File", "D:/care/ops/start-tenant.ps1"],
  "workingDirectory": "D:/care",
  "dumpExecutable": "C:/Program Files/MySQL/MySQL Server 8.0/bin/mysqldump.exe",
  "healthUrl": "http://127.0.0.1:8082/api/public/runtime-health",
  "timeoutSeconds": 180
}
```

stopCommand 必须停止并等待正确的企业进程退出；startCommand 需要启动独立后台进程后返回，不能一直占住执行命令。Windows 启动脚本的 Start-Process 应使用 -WindowStyle Hidden。生产优先通过已配置的系统服务管理器控制进程，不根据端口猜测并杀死任意程序。

执行器直接调用配置的可执行文件与参数数组，不拼接 shell 命令，不运行模块包中的安装脚本。数据库密码仅注入备份子进程 MYSQL_PWD，不放命令行。mysqldump 使用一致性事务、触发器、事件及存储过程参数；数据库账号需要相应备份权限。备份、执行日志、公钥和 runtime 目录需使用客户服务器的私有文件权限保护。

```powershell
java -jar backend/apps/installer-app/target/installer-app-2.0.0-SNAPSHOT.jar D:/care/config/installer.json --watch
# 或由服务器运维人员执行一个已经在企业后台确认的计划
java -jar backend/apps/installer-app/target/installer-app-2.0.0-SNAPSHOT.jar D:/care/config/installer.json --plan=<计划UUID>
```

企业程序对应配置：app.module-install.directory、trust-directory、runtime-directory、core-version。watch 进程写本地心跳；前端仅在心跳新鲜且进程存活时显示执行器就绪，不能通过静态布尔配置冒充在线。

## 数据迁移和失败处理

执行顺序：验证计划/签名/授权/版本依赖 → 校验 JAR 接口 → 持有执行锁并认领计划 → 停服 → mysqldump 备份并计算摘要 → 再校验授权和文件 → 模块 Flyway 迁移 → 原子切换 active-index.json → 重启 → HTTP 健康检查 + planId/包摘要/启动随机标识/进程起始时间/端口回执核对 → ACTIVE。

JAR 类定义、HTTP 前端脚本和 Flyway SQL 均取自验签后的内存快照，不会在校验后重新信任磁盘文件。模块配置使用显式 @Bean/@Import；此版内存类加载器不支持通过包目录枚举的 @ComponentScan，不能依赖它发现业务类。

模块独立迁移历史表为 flyway_module_<code>，首次安装在已有企业库上使用 baseline 0。更新包应保留完整历史迁移和原始校验和；不允许回写旧迁移，不允许同版本替换或降级。所有 migrations 文件都必须列入清单。

V11 保存执行阶段、备份路径/摘要及错误摘要；前端不暴露服务器备份路径。旧版本成功替换后标记 SUPERSEDED。程序目录按内容摘要保留，不自动删除模块业务表。

备份前或迁移前失败：尝试恢复旧索引并重启旧服务，标记 FAILED；旧服务也无法恢复则 RECOVERY_REQUIRED。只要已开始迁移或已启动新版，后续失败就停止服务并标记 RECOVERY_REQUIRED，不盲目回退旧程序。进程意外退出留下 INSTALLING/RESTART_PENDING 时，watch 不会自动重跑；运维需检查日志、备份与实际迁移结果后处理。

## 验证范围

自动测试使用隔离 H2、真实编译的外置 JAR、真实 Spring 配置注册和真实 Flyway 模块迁移验证成功链路及失败分支，不会对当前预览企业执行停服备份迁移。生产 MySQL 的 mysqldump、服务管理脚本和重启过程仍需在对应部署环境演练。
