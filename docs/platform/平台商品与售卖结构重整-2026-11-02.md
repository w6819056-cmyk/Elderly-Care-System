# 平台商品与售卖结构重整（2026-11-02）

## 已确认目标

平台工作台改为真实数据监管大屏；企业自助登记，平台审核通过才可购买。平台不采集客户的消费者、老人、门店业务数据。

## 导航与页面责任

- 工作台：数据监管大屏，展示登记企业、审核待办、实例心跳、授权状态、模块及版本、销售订单、模块销售收入、优惠券统计。删除“平台管理范围”“系统部署边界”。无权限的数据不返回，不展示伪造统计。
- 企业管理：查看自助登记信息、审核通过/驳回、审核原因与流水、企业信息维护、实例与授权查看。取消平台新建企业入口。既有企业保留与迁移，不重复创建。
- 模块中心：模块技术目录、名称/说明、版本档案、签名包上传、校验摘要、发布状态、发布新版本。已经发布的签名包不可原地覆盖；更新以新版本发布，不能只修改版本号而不更换签名包。
- 销售授权：通用报价、模块定价、套餐组合、优惠券码、销售订单。独立“套餐管理”导航合并回此处。
- 模块售卖：出售预览、模块编辑。出售预览有单模块售卖/套餐组合售卖二级选项；模块编辑有模块编辑/套餐编辑二级选项。此处不再嵌入价格编辑和套餐组合表单。

## 三层商品模型

1. 模块：程序与权限的稳定身份，使用 moduleCode。不等同于商品。
2. 单模块商品：绑定模块，拥有商品编号、显示名、介绍、计费方式、期限、价格、门店名额、币种、上架状态。未配置商品的模块不自动产生商品卡片；通过添加商品明确创建。保存后显示商品信息卡片，可修改。同一模块后续可以有多个定价商品。
3. 售卖卡片：绑定一个商品或者套餐，附加封面图片地址、展示排序、显示状态。名称、介绍、价格、期限和名额读取绑定商品，不能在宣传编辑里维护第二份价格。停用卡片不改变企业已有授权。停售商品会从出售预览隐藏。

套餐使用单模块商品为组合项，读取商品名称、模块身份、计费期限与门店名额；设置套餐名称、说明、组合价格与售卖状态。套餐也可绑定宣传卡片。不能重复包含同一模块。商品修改不修改历史订单的商品快照。

## 用户操作

新增单模块商品：销售授权 → 模块定价 → 添加商品 → 选择已收录模块 → 填写显示名称、计费方式、期限、价格、名额、介绍 → 保存。列表生成信息卡片，提供修改操作。

新增套餐：销售授权 → 套餐组合 → 新建套餐 → 选择模块定价中已有的商品 → 设置套餐名称、介绍和价格 → 保存。

新增售卖卡片：模块售卖 → 模块编辑 → 选择模块编辑或套餐编辑 → 新增卡片 → 选择现有商品或套餐 → 填写图片地址、展示排序 → 保存。预览按商品类型分组，单个商品居中显示，多商品形成扇形卡带。

## 通用报价与真实订单

通用报价不选择企业，读取商品或套餐、数量/授权方案及可用券码进行价格预览。只说明标准报价，不执行企业依赖验证、永久拥有模块抵扣或授权操作。

真实下单仍必须识别已审核的企业，由服务端校验模块正式依赖、已有授权、永久拥有抵扣、期限叠加与名额规则，计算最终价格后生成不可变快照。不能为了通用报价新增虚拟企业或跳过最终下单检查。

## 优惠券码

支持折扣券与抵扣券。建议默认每码一次使用、不叠加；创建时明确类型、折扣或金额、适用商品范围、有效期、最低消费。折扣券须明确输入例如“8折”即原价80%，抵扣后不低于零。券码随机生成且唯一。

列表显示未使用、已预留、已使用、已过期、已作废，展示适用范围、有效期和关联订单。删除未使用券按作废处理；已使用券保留交易历史与关联记录。报价不消耗券，订单创建时并发锁定；支付成功核销，订单取消或超时释放。退款与是否返券采用明确规则，不直接删除核销记录。优惠实际执行必须接入订单事务，不可仅由前端减价。

## 企业登记与审核

已确认：企业提交登记后，平台审核通过才可购买。

登记收集企业身份、名称、联系人、联系方式及必要部署信息，生成待审核记录；平台审核通过后建立可购买身份，驳回须填写原因，并可由企业修订重提。企业登记本身不能直接授予正式模块授权。登记接口需防止重复注册、冒用企业编号与重复激活；独立部署的企业初始管理员建立与平台审核凭据绑定，禁止仅凭可伪造的企业编号回传后直接开通。

现有企业数据原地保留，原有有效授权不因流程更换被清除。新登记采用独立状态与审核流水。

### 本轮接口

- GET/POST /api/platform/v1/commerce/products：查询/添加商品。
- PUT /api/platform/v1/commerce/products/{id}：修改商品；绑定模块不可更换，已被套餐引用的期限与名额变更会被拒绝。
- GET /api/platform/v1/commerce/plan-options：卡片可选套餐。
- POST /api/platform/v1/plans、PUT /api/platform/v1/plans/{code}：创建/修改套餐，原历史订单快照不变。
- GET/POST /api/platform/v1/commerce/cards：查询/保存宣传卡片。一商品或套餐一卡片，服务端校验目标与图片地址。
- POST /api/platform/v1/commerce/quote：通用标准报价；可选券码，不占用券。
- GET/POST /api/platform/v1/commerce/coupons：列表/生成券码。DISCOUNT 的80表示8折，DEDUCTION表示固定金额抵扣；均支持最低消费与到期时间。
- DELETE /api/platform/v1/commerce/coupons/{id}：作废未占用未使用的券码，保留历史记录，不做物理删除。
- POST /api/platform/v1/orders 请求可携带 couponCode：服务端锁定并预留一次性券码，订单金额和订单项同步写入优惠快照；支付后核销。
- POST /api/platform/v1/orders/{publicId}/cancel：取消待支付订单并释放预留券；带券订单不能直接改价，需取消后重下。
- POST /api/platform/v1/enterprise-applications：公开企业登记入口，生成待审核申请，不能获得平台管理员权限。
- GET /api/platform/v1/enterprise-applications：受权限保护的登记列表。
- POST /api/platform/v1/enterprise-applications/{id}/review：平台审核，要求审核说明，只有待审核申请可处理。通过时建立企业身份，未通过前没有可购买企业记录。
- GET /api/platform/v1/commerce/dashboard：受企业、模块、订单查看权限保护的平台统计。
- PUT /api/platform/v1/storefront/{code}/profile：更新模块名称与说明，不篡改已发布包的版本/签名/摘要。

### 页面

- /：数据监管大屏。
- /sales：销售授权五个工作区。
- /module-shop：出售预览、模块编辑；分别提供单模块与套餐二级选项。
- /enterprises：登记审核与既有企业管理。
- /modules：版本资料、上传新版本与发布。
- /register-enterprise：企业自助登记；平台登录页也有入口。
- 原 /plans 转到 /sales，避免出现第二个套餐管理入口。

### 当前边界

- 同一模块、计费方式和期限只能存在一个定价商品，沿用旧价格表唯一约束。若需同一计费期内按不同名额销售多个SKU，还需扩展授权报价对价格方案的唯一识别。
- 券码为全商品通用、一次性、单券不叠加。未支付券需取消订单释放，目前没有自动超时释放调度。支付后退款不自动返券。
- 公开登记目前处理平台申请与审核；客户自有服务器上的部署、初始管理员初始化、实例密钥与激活仍走现有部署流程，不会因登记申请直接部署客户服务器或创建平台管理员。
- 企业总部的自助结算页面、真实支付渠道仍需独立接入；现有支付为MOCK。不能把通用报价当作企业最终含依赖校验的结算价。
