# 消费者账号与预约查询

## 入口与边界

`/customer/register` 注册，`/customer/login` 登录，`/customer` 个人中心与我的预约。品牌、门店首页提供用户入口。员工账号及管理员账号不能当消费者账号使用。

用户身份属于当前企业独立数据库，在该企业各门店通用。V9 迁移新增账号和会话表，并为预约增加可空 customer_id，不修改历史预约归属。

## 业务流程

用户进入门店预约页，未登录时前往消费者登录或注册；登录后返回原门店预约页。新预约绑定服务端会话识别出的用户 ID，不接受客户端指定用户 ID。成功回执提供“我的预约”入口。刷新、重新登录后，从数据库重新读取该账号在企业旗下门店的全部预约和门店处理状态。

历史匿名预约仍由门店后台管理，不根据相同手机号自动认领。手机号仅用于接待联系，没有接入短信验证。当前不支持短信登录、找回密码、用户取消或会员权益。

## 接口与会话

前缀 `/api/public/customer`；虽然路径位于公开路由白名单，以下业务接口在控制器中强制校验独立用户会话。

- POST `/register`：username、password、displayName；POST `/login`：username、password。
- GET `/me`、GET `/bookings`、POST `/logout`：请求头 X-Customer-Token。
- POST `/stores/{no}/bookings`：同一请求头，预约字段沿用原预约接口。

账号不区分字母大小写，密码使用 BCrypt。会话为 256 位随机令牌，数据库仅存 SHA-256 摘要，七天过期；退出撤销当前会话。浏览器使用独立 customer.access_token 保存，员工登录状态互不覆盖。API 禁止任意查询其他用户 ID。注册及登录按 IP 限流，登录还按账号限流；当前限流是单实例内存实现。旧匿名预约接口为兼容保留，用户网页新流程使用认证接口。

## 验证

自动验证账号创建、重新登录查询持久预约、不同用户隔离、匿名拒绝、退出后令牌失效、消费者令牌不能进入员工接口，以及前端重新挂载读取记录。
