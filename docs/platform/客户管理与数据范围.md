# 客户管理与数据范围

## 入口与操作

- 企业总部：`http://localhost:5175/hq/customers`。
- 门店工作台：`http://localhost:5175/store/customers`，使用该门店员工账号。
- 总部最高管理员自动获得新权限；其他员工由总部在“角色与权限组”中分配基础权限“查看客户信息”，再分配相应角色和门店范围。刷新会话后可见导航。
- 客户由用户网站自行注册，管理端读取真实注册账号，不自动生成演示客户。
- 卡片显示昵称、账号、注册日期、可见预约数量与关联门店。详情显示最近 100 条可见预约，包含预约称呼、联系电话、日期、状态与备注。
- 搜索昵称、账号和权限范围内的预约联系电话；列表按注册时间倒序，每页 20 位客户。

## 数据规则

企业总部 ALL 范围可见企业实例所有注册用户，包含尚未预约者。指定门店或门店组范围的总部员工仅可见与范围内门店有预约关联的用户。门店账号固定为所属门店，不能通过参数切换其他门店。

同一账号关联多店时，账号身份仍相同，但本店只能看到本店的预约和联系信息。预约电话号码并非账号已验证手机号；不按相同电话自动合并账号。未绑定账号的旧预约仍在预约管理展示，不推断绑定。

这是免费基础能力。会员等级、权益及跨店会员识别仍由会员模块承载。客户账号、联系方式、预约记录不上传平台销售授权系统。

## 后端调用

携带员工 Bearer Token：

```http
GET /api/tenant/v1/customers?q=搜索内容&page=1&size=20
GET /api/tenant/v1/customers/{publicId}
```

统一响应封装 `code/message/data/traceId/timestamp`。列表 data 为 `items/total/page/size`；详情为 `customer/bookings`。权限 `core.customer.view`，无权限返回 403；不存在或越界客户详情返回 404。服务端从员工上下文获取数据范围，所有查询、计数和搜索都受相同范围约束。不返回密码散列或客户会话令牌。

新增数据库迁移 V13 登记权限及门店/客户关联索引；没有修改旧迁移、重建数据库或修改历史用户数据。
