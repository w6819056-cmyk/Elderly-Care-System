# 企业模块安装中心当前进度

## 购买版本与安装版本

企业购买的是模块授权，不是某个固定代码版本。平台销售订单和企业授权只绑定模块商品/套餐及授权期限；企业已有授权不会因平台发布新版本而自动升级。

安装中心从平台返回该企业有权下载的已发布包，并按企业当前 `coreVersion` 过滤兼容性。默认推荐同一 `moduleCode` 下版本号最高的“已发布且兼容”版本。总部也可以展开版本列表，手动选择仍可用的旧版本。安装计划会固定记录 `moduleCode`、`version` 和 `sha256`，防止确认后包内容被替换。

升级流程必须由总部明确确认：下载并校验包 → 生成安装计划 → 总部确认 → 企业本地执行器备份、迁移、重启和健康检查。新版本发布不会覆盖当前已安装版本；升级失败时保留旧版本并将计划置为 `FAILED` 或 `RECOVERY_REQUIRED`，由恢复流程处理，模块业务数据不因失败自动删除。

因此，企业首次购买会员模块后，实际安装的是安装中心推荐的兼容发布版本；企业购买行为本身不选择版本，也不会把多个代码版本叠加为多个会员模块。

入口 `/hq/module-install`。查看需要总部身份和 core.module.view；下载、确认、撤销需要 core.module.install，该权限通过 V10 加入企业所有者权限组，普通角色需手动分配。

## 已实现

平台已校验模块可手动发布。只有已发布、企业授权仍有效的版本能通过企业实例签名接口下载。管理员 JWT 不能替代实例签名。下载请求沿用时间戳、随机数、Ed25519 签名及防重放校验。

企业从平台获取版本、下载后使用本机配置的可信发布公钥再次校验，将包缓存至私有目录并创建安装计划。计划绑定模块编号、版本、包摘要，24 小时有效。确认时重验包摘要、发布签名、底座版本范围、有效授权和已安装依赖；依赖必须有正式授权。使用数据库单行锁串行化计划变更，重复确认拒绝。计划可以撤销，不删除业务数据。

## 执行器与运行时

已实现独立 installer-app、数据库备份调用、迁移执行、外置 JAR 启动加载及门店动态页面入口。executorReady 由本机执行器心跳和存活进程身份计算，默认不启动执行器。确认后的 READY_FOR_INSTALLER 只是待执行；只有执行器完成新进程健康和启动身份核对后才变为 ACTIVE。详见《模块执行器与运行时接入》。

本地预览企业尚未配置实例激活、授权同步、可信发布公钥及进程管理命令，因此仍显示执行器离线，不能冒充已经完成生产安装。旧 delivery-probe 是不可运行协议样包；新的 examples/modules/hello-module 提供可运行接口样例。

## 配置

企业实例需先配置 app.license 下的激活和授权同步参数。未配置时页面提示并禁止连接平台，不使用演示授权绕过。

- app.module-install.directory：默认 data/module-install，私有包缓存。
- app.module-install.trust-directory：默认 data/module-publisher-keys，仅存 `<keyId>.pem` 格式 SPKI 发布公钥，不存私钥。
- app.module-install.core-version：默认 2.0.0，用于校验底座兼容范围。
- app.module-install.runtime-directory：默认 data/module-runtime，原子版本索引、启动回执和执行器心跳；企业程序与执行器配置必须一致。

## 后续执行器要求

执行器需独立于企业 Java 进程，持有安装锁；在停机前再次校验计划、授权和签名，备份成功后才执行迁移。迁移前失败可恢复旧程序，迁移后失败必须进入 RECOVERY_REQUIRED，不能盲目回退旧程序继续写入。健康检查通过后才标记 ACTIVE。上述执行链路完成并实测前，页面必须保留未接入提示。
