# 模块中心：上传与校验

## 已实现和未实现

已实现签名包构建工具、共享静态校验器、平台上传/版本列表/管理员下载接口及模块中心页面。收录状态只有 VERIFIED，不会显示为已安装。尚未开放企业下载，也没有企业安装器、外置模块运行时或正式发布动作。

## 开发人员打包

1. 按《模块包规范-v1》建立 payload 目录，只包含 backend、frontend、migrations。
2. 创建 manifest-template.json，列出 ModuleDescriptor、入口与版本范围等字段，files 可以先是空对象，构建工具自动生成摘要。
3. 发布人员在仓库外保存 Ed25519 PKCS8 私钥，公钥为 SPKI PEM。
4. 执行以下命令，输出文件必须位于 payload 目录之外且尚不存在。

```powershell
node scripts/build-module-package.mjs D:\release\payload D:\release\manifest-template.json D:\keys\publisher-private.pem D:\release\membership-1.0.0.caremod
```

构建工具只用 Node 内置库，不下载依赖。它负责文件摘要、原始 manifest 字节签名和 ZIP 生成。格式、权限、依赖和版本规则仍以服务器共享验证器为准。构建成功不意味着程序符合未来运行接口。

## 平台配置

- `platform.module-packages.directory` / `PLATFORM_MODULE_PACKAGES_DIRECTORY`：私有包目录，默认 data/module-packages。
- `platform.module-packages.trust-directory` / `PLATFORM_MODULE_PACKAGES_TRUST_DIRECTORY`：可信发布公钥目录，默认 data/module-publisher-keys。
- 公钥文件必须命名为 `<keyId>.pem`，例如 publisher-v1.pem。
- 公钥目录只能由服务器管理员管理，不能让上传包自行添加公钥。私钥不能放入公钥目录或仓库；软件授权签名密钥与模块发布签名密钥分开。
- 包目录不映射成公开静态目录。备份时同时备份平台数据库和私有包目录。

没有可信公钥时上传失败，不会自动信任新发布者。升级包也需要签名且不得复用同一版本号。

## 页面与接口

平台 `/modules`：先创建草稿目录，再选择 .caremod 上传；只读账号看记录，管理权限账号可以建目录和上传。本轮不提供价格、依赖销售策略和上下架编辑页面。

- GET `/api/platform/v1/module-packages`：platform.module.view。
- POST 同路径：platform.module.manage，Content-Type: application/octet-stream，请求体为原始包。
- GET `/api/platform/v1/module-packages/{code}/{version}/download`：管理员读取，不是客户分发接口。

V5 新增 pf_module_package。通过校验后以整个包的 SHA-256 命名存储文件；同一模块版本不可覆盖；销售目录对应版本不存在时创建版本元数据，已存在时校验最低底座版本一致。收录写入平台审计。

文件先写临时文件，再原子移动，最后由事务写入数据库。数据库失败可能留下无引用包文件，但不会生成指向未完成文件的记录；后续清理只处理确认无引用的文件，当前不自动删除。下载会重新校验摘要和发布签名。

## 本地验证样包

delivery-probe 是签名与传输协议验证样例，后端类不实现安装运行接口，不可当成业务模块启用。样包、发布私钥和可信公钥放在当前用户 LocalAppData/YanglaoPreview 下，仓库不保存密钥。正式部署应重新配置正式发布密钥，不复用预览密钥。
