# 企业租户组织与权限接口（v1）

本文描述企业自己的 `tenant-app` API。所有路径以 `/api/tenant/v1` 开头；请求和响应均为 JSON。成功响应使用 `ApiResponse`，包含 `code=OK`、`data`、`traceId` 和 UTC `timestamp`。错误响应包含稳定 `code`、安全提示、`traceId` 和 UTC `timestamp`。

## 认证

### `POST /auth/login`

公开登录。请求：`{"account":"总部账号","password":"明文密码"}`。成功返回 `data.accessToken`、`expiresAt` 和员工主体。账号与密码错误统一返回 HTTP 401 / `UNAUTHORIZED`。令牌 audience 为 `TENANT_STAFF`；平台令牌、旧业务令牌不能访问本 v1 路由。

### `GET /auth/me`

需要 `TENANT_STAFF` Bearer 令牌。返回当前员工公开 ID、账号、姓名、员工域、绑定门店公开 ID、当前角色/权限和解析后的数据范围。每个请求重新查询账号状态、角色、权限及门店组成员，不以令牌中的旧权限作为授权依据。

### 首次总部所有者

首次开通仅通过环境变量配置的一次性 bootstrap，不提供公开安装 API。需显式设置 `TENANT_BOOTSTRAP_ENABLED=true` 并完整提供 `TENANT_ORG_NO`、`TENANT_ENTERPRISE_NAME`、`TENANT_OWNER_ACCOUNT`、`TENANT_OWNER_DISPLAY_NAME`、`TENANT_OWNER_PASSWORD`；所有者密码至少 12 位。bootstrap 只在本企业库尚无企业记录时创建一次，重复执行返回已初始化且不覆盖账户。不得把密码写入日志或提交到版本库。

## 总部组织

以下接口要求相应权限；除企业资料读取外，组织写入均要求数据范围为 `ALL`，范围不足时拒绝。

| 方法与路径 | 权限 | 行为 |
| --- | --- | --- |
| `GET /hq/enterprise` | `core.enterprise.view` | 读取本企业资料 |
| `PUT /hq/enterprise` | `core.enterprise.manage` | 修改 `name`、`legalName`、`contactName`、`contactPhone` |
| `GET /hq/stores` | `core.store.view` | 列出当前数据范围内门店 |
| `POST /hq/stores` | `core.store.manage` | 创建门店；请求字段 `storeNo`、`name`，可选 `regionCode`、`address`；初始状态 `DRAFT` |
| `PATCH /hq/stores/{publicId}/status` | `core.store.manage` | 请求 `{"status":"ACTIVE"}` 等白名单流转；版本冲突返回 409 |

门店状态为 `DRAFT`、`ACTIVE`、`SUSPENDED`、`CLOSED`。停用/撤店由企业总部操作；门店当前状态和角色权限都在服务端校验。

## 角色、权限组与员工

总部 IAM 接口需要 `TENANT_STAFF` 令牌。角色、权限组、员工及范围写操作分别要求目录中对应的 `*.manage` 权限；读取需要对应 `*.view` 权限。总部员工才可以管理 IAM。权限目录由租户程序注册，企业管理员只能引用已注册权限代码。

| 方法与路径 | 权限 | 请求/行为 |
| --- | --- | --- |
| `GET /hq/permission-definitions` | `iam.role.view` | 返回租户程序注册的有效权限目录 |
| `GET /hq/permission-groups` | `iam.permission-group.view` | 列出企业权限组 |
| `POST /hq/permission-groups` | `iam.permission-group.manage` | `groupCode`、`name`、可选 `description`、`permissionCodes` |
| `PUT /hq/permission-groups/{publicId}/permissions` | `iam.permission-group.manage` | 用 `permissionCodes` 全量替换权限组成员 |
| `GET /hq/roles` | `iam.role.view` | 列出企业角色 |
| `POST /hq/roles` | `iam.role.manage` | `roleCode`、`name`、`roleDomain`（`HQ`/`STORE`）、`permissionGroupCodes`、`permissionEffects` |
| `PUT /hq/roles/{publicId}/permissions` | `iam.role.manage` | 全量替换权限组和单独权限效果；效果仅为 `ALLOW`/`DENY` |
| `GET /hq/staff` | `iam.staff.view` | 列出数据范围内员工；范围外员工不返回 |
| `POST /hq/staff` | `iam.staff.manage` | 创建员工：`username`、至少 12 位 `password`、`displayName`、可选 `phone`、`staffType`、`homeStorePublicId`、`roleCodes` |
| `PATCH /hq/staff/{publicId}/roles` | `iam.staff.manage` | 用 `roleCodes` 全量替换员工角色 |
| `PATCH /hq/staff/{publicId}/disable` | `iam.staff.manage` | 停用员工；已有令牌随即失效 |
| `POST /hq/store-groups` | `iam.staff.manage` | 创建总部自定义门店组：`groupCode`、`name` |
| `PUT /hq/store-groups/{publicId}/stores` | `iam.staff.manage` + `ALL` 范围 | 用 `storePublicIds` 全量替换门店组成员 |
| `PUT /hq/staff/{publicId}/data-scope` | `iam.staff.manage` + `ALL` 范围 | 配置总部员工范围，见下节 |

权限组权限取并集；单独 `DENY` 优先于任何角色中的 `ALLOW`。角色域必须匹配员工域。受保护的 `TENANT_OWNER` 角色与其所有者员工不可被削权、停用或改范围。

## 数据范围

`PUT /hq/staff/{publicId}/data-scope` 请求包含 `scopeType`，以及按类型使用的 `storePublicIds` 或 `storeGroupPublicIds`：

- `ALL`：全部门店；不允许附带门店或组 ID。
- `STORES`：仅明确列出的门店；空集合表示无门店权限。
- `STORE_GROUP`：所选门店组当前包含的门店；组成员调整后已签发令牌立即按新成员解析。
- `SELF`：仅本人范围，不允许附带门店或组 ID。

门店员工的有效范围始终固定为其唯一绑定门店，不能通过角色或请求参数扩大。列表接口必须在服务端按解析后的门店集合裁剪；单对象写入还需校验门店状态。

## 错误与审计

| HTTP | 错误码 | 场景 |
| --- | --- | --- |
| 400 | `INVALID_REQUEST` | JSON 格式错误或 DTO 校验失败 |
| 401 | `UNAUTHORIZED` / `TOKEN_INVALID` | 凭证错误、非租户令牌、员工停用或令牌失效 |
| 403 | `PERMISSION_DENIED` / `DATA_SCOPE_DENIED` | 缺少权限或对象在当前数据范围之外 |
| 404 | `NOT_FOUND` | 企业内公开 ID 不存在 |
| 409 | `BUSINESS_RULE_VIOLATION` / `VERSION_CONFLICT` | 非法状态流转、受保护对象修改或并发版本冲突 |
| 422 | `BUSINESS_RULE_VIOLATION` | 未注册权限、错误角色域、非法编码或字段组合 |
| 500 | `INTERNAL_ERROR` | 未预期的服务端错误；不返回 SQL 或内部异常细节 |

组织和 IAM 的状态修改在同一事务写入租户审计，记录操作者、动作、目标公开 ID、traceId 和非敏感摘要。企业数据库由企业自己持有；平台控制面不读取员工、客户或经营数据。
