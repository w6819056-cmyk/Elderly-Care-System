# 模块权限注册与岗位预设

## 权限分组
权限目录来自企业服务端，按 moduleCode 自动生成按钮。core 显示基础经营，iam 显示组织与权限，业务模块名称来自 ModuleRegistry。切换模块不会丢失其他模块勾选；可全选/清除当前模块。角色中可以分别允许、禁止，DENY 优先。角色权限不替代模块购买、启用和门店名额。

## 新模块接入
模块描述符继续声明 permissionCodes。新增模块可注册实现 ModulePermissionLabels 的 Spring Bean，通过 permissionNames() 返回权限编码到中文名称的映射。企业启动注册器写入/更新中文名称，并校验权限归属。页面无需增加硬编码模块菜单。没有中文元数据的新增权限显示待完善名称，编码只作为辅助信息。

## 岗位预设（V7）
平台超级管理员保持平台系统原配置，不在企业数据库重复创建。

每个企业预置同名权限组与角色，编码使用 PRESET_（组）/TPL_（角色）前缀，不自动绑定任何员工，不改已有自定义角色。
- 企业超级管理员：全部当前基础经营与组织权限，不含平台权限，新模块手动配置。
- 企业运营主管：门店管理、模块启停/名额分配、咨询预约、员工查看。
- 区域经理：门店/员工/授权查看、咨询处理；必须另外配置负责门店范围，不自动设 ALL。
- 企业人事主管：门店查看、员工管理、角色查看；不能修改角色权限。
- 企业财务：当前空权限模板，待财务模块落地后配置。
- 企业只读督导：基础资料、组织及咨询只读。
- 店长、副店长、门店前台：本店咨询预约查看及处理，不包含总部组织与授权管理。
- 护理人员：当前空权限模板，待护理业务模块授权后配置。
- 门店财务：当前空权限模板，待财务模块落地。
- 门店只读员工：本店咨询预约查看。

店长与副店长目前基础权限相同，接入订单、退款、财务模块后由企业细分。财务和护理模板在 UI 明示待配置，不将空模板描述为已有业务能力。预设可以由企业管理员编辑，未来模块注册不自动扩展这些普通岗位权限。
